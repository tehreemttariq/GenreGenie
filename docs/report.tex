\begin{abstract}
This report presents Deliverables 1 \& 2 for the \textbf{GenreGenie} project, developed collaboratively by Aina Asad (l242519) and Tehreem Tariq (l242590). GenreGenie addresses choice overload on streaming platforms by implementing collaborative filtering models trained on MovieLens data enriched with TMDB API metadata. We document the complete machine learning pipeline from problem definition through data preprocessing, model architecture design, training with hyperparameter optimization, and rigorous evaluation including error analysis and bias detection. The project demonstrates professional software engineering practices with modular code architecture and comprehensive Git version control.
\end{abstract}

\section{Phase 1: Problem Definition}

\subsection{Problem Statement}
In the modern digital entertainment ecosystem, users face choice overload due to thousands of movies available across platforms. Standard keyword searches or static top-chart listings fail to adapt to dynamic user tastes. Streaming telemetry generates rapid, high-dimensional user interaction streams (e.g., watch ratios, ratings, skips). \textbf{GenreGenie} transforms raw movie streaming telemetry into dynamic, personalized recommendations by merging TMDB's live metadata API with collaborative user behavior modeling.

\subsection{Target Audience}
\begin{itemize}
    \item \textbf{End Consumers}: Viewers who experience choice paralysis and require hyper-personalized content feeds.
    \item \textbf{Streaming Service Developers}: Platform operators seeking hybrid recommender architecture (combining real-time API metadata enrichment with collaborative interaction matrix models).
\end{itemize}

\subsection{AI Justification}
Traditional rule-based programming (e.g., IF genre == 'Action' THEN recommend top-rated Action movie) falls short due to:
\begin{enumerate}
    \item \textbf{High Dimensionality \& Latent Patterns}: Human viewing behavior depends on latent interactions (e.g., preference for specific director-actor combinations or temporal mood shifts) that cannot be hardcoded into deterministic rule sets.
    \item \textbf{Scalability}: Rule-based trees scale non-linearly with $O(N \cdot M)$ complexity as users ($N$) and items ($M$) grow, rendering static conditional logic obsolete.
    \item \textbf{Matrix Factorization \& Collaborative Patterns}: Machine Learning approaches (e.g., Matrix Factorization / Neural Collaborative Filtering) optimize continuous loss functions over high-dimensional sparse user-item interaction matrices:
    \begin{equation}
        \min_{P, Q} \sum_{(u,i) \in R} \left( r_{ui} - \mathbf{p}_u^T \mathbf{q}_i \right)^2 + \lambda \left( \|\mathbf{p}_u\|^2 + \|\mathbf{q}_i\|^2 \right)
    \end{equation}
    where $P$ and $Q$ represent latent embeddings for users and items respectively.
    \item \textbf{Dynamic Adaptation}: ML models support continuous retraining as new user interactions arrive, enabling temporal personalization impossible with static rule databases.
\end{enumerate}

\subsection{Feature Engineering Strategy}

Our feature engineering pipeline (\texttt{03\_feature\_strategy.py}) implements multiple preprocessing techniques:

\subsubsection{Normalization \& Scaling}
\begin{enumerate}
    \item \textbf{Min-Max Normalization} (User Features):
    \begin{equation}
        x_{\text{norm}} = \frac{x - x_{\min}}{x_{\max} - x_{\min}}
    \end{equation}
    Applied to: rating count, rating mean (normalized to [0,1] range)
    
    \item \textbf{Standard Scaling} (Movie Features):
    \begin{equation}
        x_{\text{std}} = \frac{x - \mu}{\sigma}
    \end{equation}
    Applied to: number of ratings, average rating (zero mean, unit variance)
\end{enumerate}

\subsubsection{Categorical Encoding}
\begin{itemize}
    \item \textbf{Label Encoding}: Genre categories mapped to integer indices
    \item \textbf{Feature Extraction}: Primary genre extracted from multi-genre strings
    \item Future work: One-hot encoding for multi-label genre classification
\end{itemize}

\subsubsection{Engineered Features}
\textbf{User-Level Features:}
\begin{itemize}
    \item Rating count (activity level)
    \item Mean rating (user preference baseline)
    \item Rating standard deviation (rating consistency)
\end{itemize}

\textbf{Movie-Level Features:}
\begin{itemize}
    \item Number of ratings (popularity proxy)
    \item Average rating (quality indicator)
    \item Rating variance (polarization measure)
    \item Genre encoding
\end{itemize}

\section{Phase 3: Model Development \& Training}

\subsection{Machine Learning Framework}

We used \textbf{Scikit-Learn} to develop and train collaborative
filtering models for movie recommendations. The framework provides
efficient tools for matrix factorization, nearest-neighbor search,
and model evaluation.

The project implements the following models:

\begin{itemize}
    \item \textbf{Matrix Factorization (SVD):} Uses latent factors
    to identify hidden relationships between users and movies.
    \item \textbf{Collaborative Filtering Baseline:} Predicts ratings
    using the global average, user rating bias, and movie rating bias.
    \item \textbf{K-Nearest Neighbors (KNN):} Uses similarity between
    movies to generate recommendations. Its results will be included
    after its training and evaluation are completed.
\end{itemize}

\subsection{Model Architecture}

The recommendation pipeline converts user ratings into a
user-item matrix. The matrix is then used to train collaborative
filtering models, which generate predicted movie ratings.

\subsection{Dataset Preparation}

The MovieLens ratings dataset contains approximately 100,836
ratings from 610 users across 9,724 movies.

We divided the dataset into three subsets:

\begin{itemize}
    \item Training set: 70\% (70,584 ratings)
    \item Validation set: 15\% (15,126 ratings)
    \item Test set: 15\% (15,126 ratings)
\end{itemize}

The training data was converted into a user-item rating matrix
of shape $(610, 8607)$, with approximately 98.66\% sparsity.

\subsection{Model Training}

\textbf{1. Matrix Factorization (SVD)}

We implemented Scikit-Learn's \texttt{TruncatedSVD} to reduce
the rating matrix into a smaller latent-factor representation.
The model uses user and movie latent factors to estimate ratings.

The prediction formula is:

\begin{equation}
\hat{r}_{ui} = \mu + \mathbf{p}_u^T \mathbf{q}_i
\end{equation}

where $\mu$ is the global average rating, and
$\mathbf{p}_u$ and $\mathbf{q}_i$ represent user and movie
latent factors.

\textbf{2. Collaborative Filtering Baseline}

The baseline model predicts ratings using the global mean,
user bias, and movie bias:

\begin{equation}
\hat{r}_{ui} = \mu + b_u + b_i
\end{equation}

where $b_u$ represents user bias and $b_i$ represents movie bias.

\textbf{3. K-Nearest Neighbors (KNN)}

KNN uses cosine similarity to identify movies with similar
rating patterns. Recommendations are generated using ratings
from similar movies. Its final performance will be reported
after the model is trained and evaluated.

\section{Phase 4: Model Evaluation \& Validation}

\subsection{Evaluation Strategy}

We used a 70/15/15 training, validation, and test split.
The validation set was used for model selection and
hyperparameter tuning, while the test set was used to measure
final model performance.

\subsection{Evaluation Metrics}

Since GenreGenie predicts numerical movie ratings, we use
the following regression metrics:

\textbf{Root Mean Squared Error (RMSE):}

\begin{equation}
RMSE = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2}
\end{equation}

RMSE penalizes larger prediction errors more heavily.

\textbf{Mean Absolute Error (MAE):}

\begin{equation}
MAE = \frac{1}{n}\sum_{i=1}^{n}|y_i-\hat{y}_i|
\end{equation}

MAE measures the average absolute difference between actual
and predicted ratings.

Lower RMSE and MAE values indicate better rating predictions.

\subsection{Precision, Recall, and F1-Score}

RMSE and MAE evaluate rating prediction accuracy, but they
do not measure how effectively the system retrieves relevant
movies.

For recommendation evaluation, ratings can be converted into
relevant and non-relevant labels using a defined rating
threshold, such as 4.0 or above.

\begin{equation}
Precision@K =
\frac{\text{Relevant recommended movies}}
{\text{Total recommended movies}}
\end{equation}

\begin{equation}
Recall@K =
\frac{\text{Relevant recommended movies}}
{\text{Total relevant movies}}
\end{equation}

\begin{equation}
F1 = 2 \times
\frac{Precision \times Recall}{Precision + Recall}
\end{equation}

Recommendations are ranked by predicted rating, exclude movies
seen in training, and use ratings of 4.0 or higher as relevant.
On the held-out test set, the validation-selected Baseline
achieved Precision@10 = 0.0005, Recall@10 = 0.0019, and
F1@10 = 0.0008 across 585 users with at least one relevant
held-out rating. These low ranking scores show that good rating
regression metrics do not translate to strong top-10 retrieval
quality for this baseline.

\subsection{AUC-ROC}

AUC-ROC measures how well a model distinguishes relevant
movies from non-relevant movies across different classification
thresholds. It can be calculated by defining positive ratings
(e.g., ratings of 4.0 or above) as relevant and the remaining
ratings as non-relevant.

AUC-ROC is not included in this evaluation run; the reported
ranking metrics assess the top-10 list directly.

\subsection{Error Analysis and Bias Check}

Error analysis helps identify cases where predicted ratings
differ significantly from actual ratings.

The error analysis is performed on held-out predictions from the
Baseline model, selected using validation RMSE. The low-activity
cohort had RMSE 1.0087 (910 ratings), compared with RMSE 0.8855
(11,276 ratings) for the high-activity cohort. Among genres with
at least 30 test ratings, Mystery had the lowest MAE (0.6447,
1,122 ratings) and Horror the highest (0.7364, 1,054 ratings).

The top 20\% most-rated movies accounted for 0.0\% of recommendation
slots despite comprising 20.0\% of the candidate catalog. Drama
represented 59.9\% of recommendation genre memberships versus
19.8\% of catalog genre memberships. These are descriptive
comparisons; movie genres overlap, and the available data has no
demographic attributes for protected-group fairness evaluation.
